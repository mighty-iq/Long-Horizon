# PWA and in-app browser notes (core)

## Install and offline (GitHub Pages copy only)
- **Files:** `manifest.webmanifest` (name/short_name Long-Horizon, `start_url` ".", `scope` ".", `display`
  standalone, `categories` ["education"], `background_color` #EEF2F1 = light `--hf-bg`, `theme_color` #0F2A3A = `--hf-deep`; icons 192, 512
  and a 512 maskable), `sw.js`, `assets/icons/` (icon-192, icon-512, icon-maskable-512, apple-touch-icon 180,
  favicon-32; opaque PNGs drawn from the kelp mark of `HF.ui.c.mark()`: deep ink background, light strokes,
  orange float; the maskable one keeps the mark inside the central 80 % circle). Regenerate the icons with
  `python3 tools/make-icons.py`.
- **index.html** (written by `node tools/sync-index.mjs`): `<!-- hf:head -->` = theme-color for light and dark
  plus the favicon (kept in every build; the single-file build inlines the favicon); `<!-- hf:pages-only -->` =
  `<link rel="manifest">` and the apple-touch-icon (dropped by the single-file build).
- **sw.js:** the block between `// hf:sw:start` and `// hf:sw:end` is generated by `sync-index.mjs` from
  `js/manifest.json`: `PRECACHE` = `./`, index.html, manifest, every stylesheet and script the page loads, the
  letter clips and the icons (98 files now); `VERSION` = the first 12 hex digits of a SHA-256 over those files
  (the newly written index.html included). **Run `node tools/sync-index.mjs` before every deploy**;
  `--check` fails when index.html or sw.js is stale.
- **Behaviour:** install precaches everything into `long-horizon:<registration scope>:<VERSION>` (the scope keeps
  two deployments on one origin apart, e.g. two repos of one github.io account: activating one deletes only its
  own older caches, never the other's — CB-09); the first install takes control at
  once, so offline works from the first visit. Fetch: same-origin GET only (the Discord link and other origins
  are never touched), cache-first, navigations included (offline launches get index.html), a miss goes to the
  network and is stored. Updates: the browser re-checks sw.js on launch; a changed file means a new version,
  precached by a new worker in the background, which then waits. The app shows a toast "A new version of Long-Horizon
  is ready." with **Reload**; that posts `skip-waiting` and the page reloads once on `controllerchange`. Without
  the click the new version starts when every Long-Horizon tab is closed. Two versions' files are never mixed.
  Older caches of the same scope are deleted on activate, including 1.0.0's caches under the working name's prefix
  (`OLD_PREFIXES` in sw.js; 13 Nov rename).
  (The brief asked for "cache-first with background update". Refreshing cached files one by one in the
  background could mix two versions' files, so the background update is the new worker precaching the whole
  next version.)
- **Registration (js/app.js):** only when the page is served over https or http://localhost / 127.0.0.1, is
  top-level (not in a frame or srcdoc preview), has the manifest link, and is not the single-file build
  (`window.HF_SINGLE_FILE`, set first in `dist/long-horizon.html`). Never on file://. Registered after `load`.
  `HF.pwa = { state: 'off'|'pending'|'registered'|'failed', reason: 'file'|'frame'|'insecure'|'single-file'|
  'no-manifest'|'unsupported'|null, registration, update: null|'ready'|'activating' }`.
- **Storage note:** the service worker caches files only; progress stays in localStorage
  (`long-horizon.v1.*`; 1.0.0's keys are copied once by the store) as before.

## In-app browser notice
- `HF.util.inAppBrowser(userAgent)` (pure, unit-tested) → `{ id, name }` or null. It recognises Discord,
  Instagram, Messenger, Facebook (FBAN/FBAV/FB_IAB), LINE, TikTok (BytedanceWebview, musical_ly, trill_), Snapchat,
  WeChat (MicroMessenger) and any Android WebView (`; wv)`; name null).
- `js/app.js` shows a calm info notice (`HF.ui.c.notice`) at the top of the current screen, with the title
  "You're in Discord's built-in browser." (or "an app's built-in browser." for unknown apps) and the text "Open
  Long-Horizon in Safari or Chrome so your progress is saved reliably." It has two buttons:
  - **Copy link** copies the page URL without its hash through `HF.dom.copyText`. If the clipboard is refused,
    a `HF.ui.c.copyBox` with the link appears.
  - **Got it** removes the notice and stores `long-horizon.v1.iab-dismissed = '1'` (try/catch), so the notice is
    shown once per device until dismissed.
- The notice is re-placed after each route change. A small style rule hides it while a block runs
  (`html[data-busy]`) or the shell hides its chrome (`.hf-app--bare`). If a block is already running at boot,
  showing it waits. `HF.env = { inApp, notice }`.

## Tests
- `tests/e2e/test_core_pwa.py` stages a copy of the site under `out/core`, serves it on 127.0.0.1 and checks:
  - registration and control of the page;
  - one versioned cache holding every precached file;
  - offline (`context.set_offline`), a reload and a navigation to `./` both boot with 0 errors;
  - a changed sw.js version shows the Reload toast, takes over and deletes the old cache;
  - `dist/long-horizon.html` never registers.
- `tests/e2e/test_core_iab.py` uses spoofed user agents:
  - Discord iOS: wording, placement, survives route changes, hidden during a block, Copy link, Got it
    remembered across a reload;
  - Android WebView: generic wording; with the clipboard refused, the copy box appears;
  - desktop Chrome: no notice.
- `test_core_index.py` checks `HF.pwa` is off on file://; `test_core_srcdoc.py` checks it is off in the single file.
